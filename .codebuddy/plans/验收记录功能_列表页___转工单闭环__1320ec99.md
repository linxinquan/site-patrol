## 产品概述

为「拍照验收」新增一个事后工作台「验收记录」：集中浏览、筛选、追溯当前项目全部拍照验收记录，并可将 AI 识别缺陷一键转为「缺陷工单」，闭环「验收 → 缺陷」数据链路。

## 核心功能

- 首页 8 宫格以「验收记录」卡片替换原「图层索引」卡片（图标 clipboardCheck、副文案动态显示记录总数如「N 条」），点击进入独立路由 `/capture-records`
- 验收记录列表页：顶部状态条（累计 / 今日 / 待整改三组统计）、时间 Tab 切换（全部 / 今日 / 本周）、楼层筛选弹层、按时间分组（今日 / 昨日 / 更早，可折叠）的缩略图瀑布网格
- 列表项点击复用 `StoredDetailSheet` 底部弹层（照片、AI 结果、描述、删除），删除同步本地存储与照片文件
- 转工单闭环：详情弹层每条 AI 缺陷卡下「转工单」按钮 + 底部「批量转工单（N）」；生成 `Defect` 写入缺陷库（带照片、部位、图纸坐标），`/defects` 立即可见；原始记录 `defects[].status` 由 `pending` 回写为 `converted`，防重复生成；Snack 提供「去缺陷列表」直达入口
- 页面底部 FAB「拍照」跳转 `/capture` 新增记录，返回后列表自动刷新

## 技术栈

- Flutter + flutter_riverpod（沿用项目现有堆栈）；GoRouter 路由；LocalStorage 抽象（`lib/core/storage/local_storage.dart`）；AppTokens 设计令牌；lucide_icons_flutter

## 关键事实修正（以代码现状为准）

- **存储键名**：方案全文的 `capture_records` 实为 **`stored_vision_results`**（`capture_page.dart` L113），读写走 `LocalStorage.instance.readDoc/writeDoc`，值为 `List<Map<String, dynamic>>`，新记录插头部（天然 ts 倒序）
- **记录结构**：`{id, drawingKey, worldX, worldY, ts, anchor, floor, count, defects:[{name, severity, conf, desc, status}], note, photo}`
- **项目隔离**：`Drawing` 无 `projectId`，按「记录.drawingKey ∈ 当前项目图纸 key 集合」过滤（`is7DongProjectProvider`/`drawingsProvider` 决定集合；drawingKey 为空的记录归属不明，予以保留）
- **详情复用**：`StoredDetailSheet`（`capture_page.dart` L2606）是公开类，新页面直接 import 复用；其 `onDelete`/`onConvertDefect` 由父级注入，弹层不持有业务状态
- **缺陷库**：`Repository.addDefect(Defect)` 已存在（Mock 为内存态，会话内可见）；`refreshDefects(ref)` 已存在；`defectsProvider` 按当前项目分组

## 实施策略

### 1. 数据层（providers.dart + models.dart）

- `Defect` 构造函数新增可选命名参数 `photos`（`List<String>`，默认 `[]`）与 `sourceCaptureId`（`String?`，默认 `null`），向后兼容所有既有调用
- 新增 `captureRecordsProvider = StateNotifierProvider<CaptureRecordsNotifier, List<Map<String,dynamic>>>`：内部持有**完整列表 `_all`**（跨项目），`state` 为按当前项目过滤 + ts 倒序后的列表；`_load()` 读文档 → 按项目图纸 keys 过滤 → 排序；`reload()` 重读；`delete(id)` 从 `_all` 移除、写回文档、删除照片文件（`LocalStorage.deleteFile`）、刷新 state——**删除必须基于完整列表**，避免误删其他项目记录
- 新增 `captureRecordsFilterProvider`（StateProvider）承载时间/楼层/AI 筛选状态；筛选为纯函数 `applyFilter(records, filter)` 置于 controller 文件
- 首页副文案与列表页均 `ref.watch(captureRecordsProvider)`，天然响应删除/转工单后 reload

### 2. 详情弹层与转工单（capture_page.dart）

- `StoredDetailSheet` 新增可选回调 `void Function(int idx)? onConvertDefect`（不传时行为与现状完全一致，拍照页不受影响）
- 缺陷卡区：`status == 'converted'` 显示「已转工单 ✓」禁用按钮；`pending` 显示「转工单」；用 `StatefulBuilder` 包裹缺陷列表，转工单成功后就地更新 `entry['defects'][idx]['status']='converted'` 并 setState 刷新弹层（无需重新打开）
- 底部操作区（仅 `onConvertDefect != null` 时显示）：「批量转工单（N）」，N = pending 缺陷数，为 0 禁用
- 转工单映射：`id='${captureId}#${idx}'`、`part=anchor`、`type=vlDefect.name`、`category=DefectCategory.other`、`severity=vlDefect.severity`、`status=draft`、`anchor/floor/ts/drawingKey/worldX/worldY` 透传、`tags=['验收转工单','验收#${captureId}']`、`note='${capture.note}｜${desc}'`、`seed='capture_convert'`、`photos=[capture.photo]`、`sourceCaptureId=capture.id`；`gps/alt/resp` 置空串、`reporter='验收记录'`
- 批量转：对全部 pending 索引循环 `repo.addDefect` → `refreshDefects(ref)` → 一次性回写所有 status → `captureRecordsProvider.notifier.reload()` → `AppSnack.show('已生成 N 条缺陷工单', actionLabel: '去缺陷列表', onAction: () => context.push('/defects'))`

### 3. 验收记录页面（新目录 lib/features/capture_records/）

- `capture_records_page.dart`（ConsumerWidget）：AppBar「验收记录」（右侧筛选按钮，搜索为 P1 预留不做）、状态条、Tab 条（全部/今日/本周/楼层弹层）、分组瀑布、FAB「拍照」→ `context.push('/capture')`
- 列表项卡片：96×96 缩略图（`FutureBuilder` + `LocalStorage.readFile`，Web 无图隐藏）+ ⚠️/✅ 徽标 + 部位·楼层 + 时刻·缺陷数；点击 → `showModalBottomSheet` + `StoredDetailSheet`（onDelete/onConvertDefect 由页面注入，删除后 provider 自动刷新列表）
- 时间分组：解析 `ts`（`'YYYY-MM-DD HH:mm:ss'`，替换首空格为 T 后 `DateTime.parse`）；分组「今日/昨日/本周早些天/更早」，分组头可折叠；楼层筛选按记录 floor 字段去重
- 空态：无记录时显示引导文案与「去拍照」按钮
- 性能：网格用 `GridView.builder` 懒加载；记录量大时仅当前分组构建

### 4. 入口与路由（home_page.dart + app.dart）

- 替换 home_page.dart L778-784「图层索引」卡片：`icon: LucideIcons.clipboardCheck`、`title: '验收记录'`、`subtitle: '${ref.watch(captureRecordsProvider).length} 条'`（`_QuickActions` 已是 ConsumerWidget，直接可用）、`tint: AppTokens.success`、`onTap: () => context.push('/capture-records')`
- app.dart ShellRoute 内追加 `/capture-records`（`CustomTransitionPage` 零时长过渡，与 `/capture` 一致）；ShellRoute 的 index 分支追加 `loc.startsWith('/capture-records') → index = -1`（不进 4 Tab 高亮，保留底部导航）

### 5. 测试

- `test/capture_records_test.dart`：列表加载与项目过滤、时间/楼层筛选、删除（含照片清理调用）、转工单映射与 status 回写、防重复生成（converted 后不再生成）

## 性能与可靠性

- 列表懒加载（GridView.builder）；缩略图仅构建可见项；删除/转工单基于完整列表写回，避免并发丢失
- 防重：`converted` 为终态，重复进入详情/重复点击均不重复生成
- 兼容：`StoredDetailSheet` 新回调为可选，现有 `/capture` 调用零改动；`Defect` 新字段带默认值，既有调用全部兼容

## 设计风格

延续项目现有 iOS 风设计语言（AppTokens 设计令牌 + 卡片化布局），整体采用「工程现场工作台」的克制冷峻风格：浅色底、圆角卡片、绿色品牌色点缀。列表页以 4 列缩略图瀑布为核心，弱化边框、强调照片信息密度，让总监扫一眼即可审阅现场回传。

## 页面布局

- AppBar「验收记录」：左侧返回，右侧筛选图标入口；标题 17pt 加粗
- 顶部状态条：3 个等宽统计块（累计/今日/待整改），数值 20pt 加粗、标签 11pt 弱化色，置于浅灰圆角容器内
- Tab 条：全部/今日/本周/楼层 四个胶囊式标签，选中态绿色品牌底 + 白色文字，未选中灰底
- 分组瀑布：分组标题（今日（18））11pt 加粗灰字 + 可折叠箭头；4 列缩略图网格，卡片圆角 8、白底细边框，缩略图左下角 ⚠️/✅ 圆角徽标表示 AI 是否识别到缺陷
- 详情弹层：复用 StoredDetailSheet，缺陷卡为浅灰底圆角容器，右侧置信度 11pt；pending 缺陷显示绿色「转工单」小按钮，converted 显示灰色「已转工单 ✓」
- FAB：绿色品牌 extended 形态，相机图标 + 「拍照」文字，悬浮右下角
- 微交互：卡片按压缩放反馈、分组折叠动画（AnimatedCrossFade）、弹层拖拽收放

## 响应式
